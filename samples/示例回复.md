# 接口改造与新模型上线（示例回复）

这次改造整体上做完了：新接口已经在灰度阶段跑了三天，10% 的流量下没有出现静默失败。但先说一段局限性声明——目前的数字只覆盖校内网络环境，校外弱网下的表现还没测。

## 关键数字

| 指标 | 上一版 | 本版 |
|---|---|---|
| 情感分类 Macro-F1 | 0.71 | 0.78 |
| 拒识率 | 12.4% | 8.1% |
| 接口 P95 延迟 | 640ms | 210ms |

## 管线

1. 采集课程评价，每天一次
2. 清洗与去重
3. 情感分类模型打分
4. 写入看板数据库

阈值写在配置文件里：

```python
CONFIDENCE_THRESHOLD = 0.55  # 低于此值走降级策略
```

> 评价入库这一步必须幂等：同一条评价重跑三次，库里也只能有一条记录。

模型侧还是老问题：类别不平衡。好评占七成多，差评样本很少，所以 Macro-F1 比总体准确率更能反映真实水平。训练数据里还有相当比例的标签噪声——标注是几个同学分工做的，标准不完全一致。理论上还存在数据泄漏的风险：同一门课的评价如果同时进了训练集和测试集，分数就会虚高，这次已经按课程做了切分。

接口层做了三件事。一是给调用方一份契约，字段名和类型固定，不再随手加字段。二是把模型调用包在 hook 里，超时或报错就触发降级，回落到上一版的规则打分，不让用户直接看到失败。三是保留回滚开关，出问题一条命令退回旧版本。

拒识率从 12.4% 降到 8.1%，但这不是错误率下降——判得更果断，不等于判得更对。

下一步想加一个基线对照组，用最简单的关键词规则跑一遍，确认模型确实比它强，而不是只跟自己的上一版比。
