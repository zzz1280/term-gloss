agent 示例回复

这次改造整体上做完了：新接口已经在灰度阶段跑了三天，10% 的流量下没有出现静默失败。但先说一段局限性声明——目前的数字只覆盖校内网络环境，校外弱网还没测。

模型侧还是老问题：类别不平衡，好评占七成多，所以 Macro-F1 比总体准确率更能反映真实水平；训练数据里还有相当比例的标签噪声，标注是几个同学分工做的，标准不完全一致。理论上还存在数据泄漏的风险——同一门课的评价如果同时进了训练集和测试集，分数就会虚高。

接口层做了三件事：给调用方一份契约，字段名和类型固定；把模型调用包在 hook 里，超时或报错就触发降级，回落到上一版的规则打分；保留回滚开关，一条命令退回旧版本。

管线还是采集、清洗、打分、入库四步，阈值写在配置里；入库必须幂等，同一条评价重跑三次也只能是一条记录。拒识率从 12.4% 降到 8.1%，但这不是错误率下降——判得更果断，不等于判得更对。下一步想加一个基线对照组，用关键词规则跑一遍，确认模型确实比它强。

点文中任意术语收入，再点一次取消。导出的 JSON 就是词库的雏形。

    这一页不依赖脚本：悬停解释由 CSS 的 attr() 渲染，三档切换是纯 CSS 单选按钮。脚本只负责生词本——即使脚本被环境禁用，正文和悬停依然可用。 真实实现里，术语表由「本地词库命中 + 模型补位」生成，结构是 {term, start, end, brief, misread}——模型只给数据，不写正文。
