# term-gloss

让 agent 的回复**保留原词**的同时，把技术黑话解释清楚——不替换，只加注释。

*Inline glosses for AI jargon: keep the term, add the meaning.*

替换成大白话，当下读懂了，下次在别处看到同一个词还是不认识。所以本项目的核心约束只有一条：**原词必须留在原地**。

## 三个入口

| 入口 | 用途 | 什么时候用 |
|---|---|---|
| `prompts/术语注释规则.md` | 把"输出契约"贴进对话，让 agent 当场就按规矩说 | **现在就能用**，零成本 |
| `data/glossary.json` | 唯一词源，54 条起步词条 | 所有工具共用，改这里就全生效 |
| `tools/gloss.py` | 把一段回复渲染成"可悬停"的 HTML 阅读页 | 复盘、存档、批量整理 |

## 两种工作模式

规则不是"每遇到术语就加括号"，而是**先判密度，再选形态**：

- **行内注释（默认）**：术语稀疏时，原词后面加 ≤30 字括注，一段最多 2 条。
- **结构化解读**：术语密集时（一段 ≥3 个），不硬塞括号，改成「三句话结论 → 关键因果链 → 术语表」。

密度高还逐词加括号，只会变成括号地狱。这是 v0.1 第一次真实测试就失败的地方——那时只有一种形态，标少了没用、标满了没法读。

模式 B 开头会标明「这是重述，不是原文」，结尾提示回原文核对：它重组了结构，数字和措辞已不是原文，不能拿来核对或引用。**读懂用 B，引用用 A 或原文。**

## 快速开始

**不想碰命令行**：双击 `demo.bat`，它会渲染内置示例并在浏览器里打开。
把任意 `.md` 文件拖到 `demo.bat` 上，就渲染那一个。

```bash
# 1. 校验词库（顺手看词条分布）
python tools/gloss.py --check

# 2. 渲染一段回复
python tools/gloss.py samples/示例回复.md

# 3. 打开产物，悬停带虚线的词；点右上角可全部展开
#    samples/示例回复.gloss.html
```

其他用法：

```bash
python tools/gloss.py reply.md -o out.html      # 指定输出
python tools/gloss.py reply.md --all            # 每一处出现都标注（默认只标首次）
cat reply.md | python tools/gloss.py -o out.html  # 从标准输入
```

只用标准库，Python 3.8+，不联网。

## 词库怎么长

1. 遇到词库里没有的词 → 加进 `data/glossary.json`，`status` 写 `ai-draft`。
2. 你确认解释准确后 → 改成 `verified`。之后所有工具都以 `verified` 为准。
3. 你已经掌握的词 → 在对话里说一声"这个我懂了"，或在提示词里维护"已掌握清单"。

字段约定：

- `level`：1 = 影响结论（必须解释）｜2 = 背景（悬停即可）｜3 = 可跳过
- `brief`：说"在这里指什么"，不说字典释义，尽量 ≤ 30 字
- `misread`：最常见的那种误读。**这一栏比 brief 更重要**——不懂你会去查，误解你会直接拿错结论去做事
- `aliases`：英文、缩写、中文别称，用于匹配

## 已知边界

- **只认已收录的词。** 遇到"预写判据"这种现场造的词，脚本不会猜（宁可漏标，不要瞎标）。补词或接模型是下一步。
- **只处理 markdown 的一个子集**：标题、列表、表格、代码块、引用、粗体、行内代码。够用于 agent 回复。
- **代码块与行内代码一律不注释**——注释会破坏复制粘贴。
- **不判断"你是否已掌握"**，目前靠 `level` 和你的手动确认。
- 复制页面时拿到的是干净的原文——解释只存在于 `data-tip` / `data-brief` 属性里，由 CSS 的 `attr()` 渲染，正文 DOM 中从来没有多出一个字。
- 产出的页面**不依赖 JavaScript**：悬停提示与"全部展开"都由 CSS 完成。所以在受限环境（预览面板、邮件预览、离线阅读器）里也能正常查看。

## 为什么不让模型直接改写正文加括号

现有同类工具大多这么做，但那样有三个后果：原文被改、注释收不起来、无法统计"这个词我查过几次"。更重要的是——你一旦分不清哪句是 agent 说的、哪句是工具补的，就失去了判断它可不可信的依据，而这恰恰是你最需要的能力。

所以本项目的分工是：**模型只产出结构化注释（term / 位置 / brief / misread），渲染交给前端。** 详细论证见 `docs/调研与方案.md`。
